# 使用与部署

中文 | [English](operation.en.md)

先确认潜器的板卡、配套程序和接线属于 [哪一个型号](variants.md)。以下命令是复现入口，本次整理没有连接潜器运行这些程序。

## V4

1. 按 [V4 硬件说明](hardware-v4.md) 核对 C 板、树莓派、I²C/PWM 扩展板及供电；按 [固件说明](firmware-v4.md) 构建用户指定 `V4-ly`。
2. 树莓派与 PC 同网段。历史配置为树莓派 `192.168.138.2`、PC `192.168.138.10`；这些是示例地址，应按现场网卡修改。
3. 使用自己配置的 SSH 账户登录。原资料中的共享账户和密码不随本仓库分发。
4. 原机服务目录名为 `joystick_control`，资料记载已由 systemd 自启，但没有提供服务名、脚本或端口转发实现。先在原机确认该服务存在并补录其启动方式；没有此服务，PC 客户端不能构成完整控制链路。
5. 配置 PC 的 Python 环境并运行 [上位机导入说明](../software/v4-topside/IMPORT.md) 中的安装命令。原文环境名 `ROV-V4` 只是已有环境的名字，不是本仓库提供的可恢复环境文件。
6. PC 与手柄连接后，从 `software/v4-topside` 启动 `pc_client.py`。先查看手柄轴号、方向和目标值，再允许推进器输出。曲线版 `pc_client_plot.py` 同样会发送控制命令。

串口参数依据固件为 UART6 115200 8E1；树莓派的实际串口设备及转发方式仍需从原机程序确认。`02 10` 是状态翻转，重复发送会再次关闭。退出客户端没有明确停机帧，不应把关闭窗口当作停桨。

### V4 排错

| 现象 | 优先核对 |
| --- | --- |
| TCP无法连接 | 同网段、端口5000、原机服务是否运行、是否被其他客户端占用 |
| 已连接但无角度文本 | 串口设备、115200/8E1、UART6接线、固件启动和传感器初始化 |
| 启动后旋转或方向反常 | 手柄轴号/符号、IMU安装方向、推进器实际通道与桨向、闭环开关状态 |
| 无视频 | 摄像头服务是否存在、推流目标IP、发送/接收端口；上游SDP为5004，GStreamer示例为5600 |

原使用记录提到曾用重新烧录恢复无串口输出，但没有证明根因；它不是保证有效的通用修复。先保存故障信息并检查链路，不把反复烧录写成必需启动步骤。

## V4-pro

1. 按 [V4-pro 硬件说明](hardware-v4-pro.md) 完成 A 板、Jetson、IMU、电调与传感器接线。
2. 依据实物选择 [FineSUB pro1 / pro2](../firmware/v4-pro/variants/README.md)，核对端口、方向和参数后构建。没有实物证据时不能自行认定 pro1/pro2。
3. Jetson 与 PC 直连网线先联调。资料示例 Jetson `192.168.0.2`、PC `192.168.0.1`；转发脚本、视频脚本和 PC 端都要使用一致的地址。
4. 相机接 USB，Jetson `/dev/ttyTHS1` 接 A 板 UART3；采用 GND共地、TX接RX、RX接TX，移除这条串口线的5 V供电线。设备节点取决于实际载板，不能仅凭 Orin 型号推断。
5. 按 [Jetson README](../software/v4-pro-jetson/README.md) 安装依赖并手动测试控制转发和视频。原来的启动脚本硬编码个人目录，作为历史记录保存；推荐用 `deploy/` 的独立服务模板，先修改路径、用户和权限再启用。
6. 配套 PC 手柄数据必须符合 UDP41字节格式；当前 V4 TCP 客户端不兼容。通过调试器观察接收状态、通道目标和传感器值，再进行有约束的执行器验证。

视频接收可按 Jetson README 的 H.264 / UDP5600 示例。原 GStreamer 脚本的 raw 分支和 CPU回退存在已记录的问题；没有摄像头和 Jetson 时，仅能完成命令构造检查，不能宣称视频可用。

## 共同的装配与水密顺序

先检查加工件和密封件，再完成离舱电气连接；验证极性、供电、电调中位和传感器反馈后装舱。按原制作记录，初次静水水密检查时移除电池，确认无漏水后再安装电池。此步骤不等于额定深度耐压测试。试验中记录硬件、固件提交、具体配置、标定与故障现象；不同潜器的结果不能相互替代。
